## 3. Root causes (condensed — see `anomaly_log.md` for full detail)

1. **`sync_broker_state()` ran real reconciliation logic in paper mode**,
   where `FyersBroker.get_positions()` unconditionally returns `[]` (no
   persistent broker-side state across restarts) — every locally tracked
   position looked "confirmed closed by the broker" on every single
   reconnect. Fixed: skip reconciliation entirely when `broker.paper_mode`.
2. **`compute_reconciliation()` reconciled against the wrong symbol** —
   the `active_positions` dict key (deliberately the *underlying*, e.g.
   `NSE:NIFTY50-INDEX`, not the traded option) instead of
   `local_pos.symbol` (the real instrument, e.g. `NSE:NIFTY2681123750CE`).
   This means reconciliation has likely never worked correctly for any
   option position in this codebase's history — masked until now because
   every existing test happened to use the same string for both. Fixed:
   reconcile against `local_pos.symbol`; added a `local_key` field so the
   caller deletes the right dict entry.
3. **The reconnect storm itself was a crash bug, not network flakiness**:
   the premium-throttle fix added an early `time.monotonic()` call inside
   `on_tick()`; two pre-existing, now-redundant local `import time`
   statements deeper in that same function made `time` function-scope
   local in Python, so the new earlier reference crashed with `cannot
   access local variable 'time'` almost every tick cycle.
   `fyers_broker.py` mislabeled this as "WebSocket disconnected," causing
   a reconnect every ~2–5 minutes — each one re-triggering bug #1/#2 on
   whatever position happened to be open. Fixed: removed both redundant
   local imports (`time` is already imported at module level).

All three fixed, covered by regression tests (6 new: 2 in
`test_reconciliation.py`, 4 in `test_risk_daily_reset_ist.py` /
`test_risk_management.py` for the carried-over equity-persistence fix),
full suite 125/125 passing. Verified live: reconciliation now correctly
skips in paper mode with no false closures, and the engine ran with zero
disconnects post-fix versus one every 2–5 minutes before.

## 4. Data integrity — full reset, not a patch

`state.db`'s equity ended up an unrecoverable mix of: real trading, 3
bug-driven false closures with fabricated exit prices, `NIFTY-RATELIMIT-TEST`
rows, and one fabricated ₹15.9L "profit" from my own live-verification
test using an unrealistic synthetic symbol. Rather than guess at a
corrected number, did a full clean reset with backup — same procedure as
the 2026-08-03 §0 baseline. User explicitly confirmed this approach over
a manual/surgical alternative.

The `NIFTY-RATELIMIT-TEST` rows reappeared a second time *after* the
reset, from my own subsequent `pytest tests/` runs — not leftover
pollution as first assumed. `tests/test_order_rate_limit.py` calls the
real `/api/order/execute` endpoint with `record_trade()` left unmocked,
writing into the real `state.db` on every suite run. This was already a
documented, named hazard from 2026-08-03 ("this will keep recurring
every time the suite runs here") that got re-triggered instead of fixed.
Fixed properly this time by mocking `shared.state.record_trade` — see
the `fix(tests)` commit. Cleaned the resulting rows out of `state.db`
again afterward; verified the full suite now leaves it untouched.
