## 3. Root causes (condensed — see `anomaly_log.md` for full detail)

1. **A second incremental-`Series.__setitem__` call site sharing the
   2026-08-06 livelock's signature.** `registry.py` built its
   post-institutional-filter signal Series via two incremental
   boolean-mask assignments; one `py-spy` dump caught it inside the exact
   `Series._set_with_engine -> Index.get_loc -> Series.__repr__` chain
   from that day's actual livelock dumps. Fixed by building the result
   with a single `np.select` call instead, eliminating the
   `Series.__setitem__` calls entirely. Bit-identical to the old
   behavior; 4 new tests.
2. **No entry-side cutoff matching the exit engine's own EOD square-off
   time.** `is_market_open()` (2026-08-06) only gates the 09:15-15:30
   window; it has no opinion on `SmartExitEngine`'s separate, tighter
   15:15 EOD-exit time. A signal in the last ~15 minutes of the session
   could open a position that the very next exit-check tick would
   immediately force-close — real (if brief) position risk and daily-cap
   consumption for zero intended trading. Fixed by adding
   `is_before_eod_cutoff()`, deliberately pinned to
   `SmartExitEngine.eod_exit_time`'s default via a dedicated test so the
   two constants can't silently drift apart again.

Both fixed and unit-tested; only #1 has live post-fix observation before
today's session ended. 16 new tests for #2, full suite: 333 passed (317 +
16), no regressions. Two commits, both local, neither pushed.
