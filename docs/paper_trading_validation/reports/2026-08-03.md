## 3. Root-cause analysis: the exit was never possible, by design gap

This is the headline finding, more consequential than the entry-blocking
bugs fixed earlier today.

**The mechanism:** `trading_bot/main.py`'s `on_tick()` only evaluates
exit conditions for an open position when the *incoming tick's symbol*
matches `position.symbol` exactly, or (fallback) matches the base symbol
for non-option positions. The live stream only ever subscribes to the
underlying index (`NSE:NIFTY50-INDEX`) — never to the option contract
itself — and no code anywhere polls the option's own price after entry
(`broker.get_market_data()` is called exactly once in the whole file, at
entry). A comment at `main.py:702` references an "EOD exit at 15:15 IST"
that does not exist anywhere in the code.

**Net effect: once an option position opens, it is structurally
impossible for the system's own stop-loss, target, trailing-stop, or
end-of-day rules to ever fire.** The position can only close via manual
intervention.

**Quantified impact, using the option's actual price history today**
(`NSE:NIFTY2680424600PE`, fetched post-close):

| Time | O | H | L | C |
|---|---|---|---|---|
| 10:35 (first candle after entry) | 74.50 | **77.70** | **71.00** | 71.50 |

Within the *first five minutes* after entry, the premium swung through
both the configured target (77.68) and stop-loss (74.71). Had the exit
mechanism worked at all, this trade would have closed almost immediately
— for a small win or a small (0.45%-capped) loss, exactly as designed.
Instead it stayed open, unmanaged, for the rest of the session. By the
15:35 candle the premium had fallen to ~59.60 (low of day 52.10) — a
mark-to-market unrealized loss of roughly -21% to -30% on premium, purely
because the risk controls never got a chance to run. `state.db` still
shows `pnl=0.0` because the trade is still technically "open," which
understates the real risk exposure that occurred.

This is exactly the class of failure §2.7/§2.8 of the checklist exist to
catch before real money is at risk — a risk control that looks correct
in isolation but never actually executes in the live path.

## 7. Recommendations

1. **Fix the exit-monitoring gap (§3) before counting any further
   validation sessions.** This is the most severe finding of the day —
   more severe than the entry bugs, because it silently disables risk
   management rather than blocking a trade. Proposed approach: when an
   index tick arrives and an open option position exists for that base
   symbol, fetch the option's own live premium via the same
   `broker.get_market_data()` call already used at entry, and run the
   existing exit-condition logic against that price. This is a
   plumbing/data-availability fix (making exit checks *run at all*), not
   a change to *what* triggers an exit — the SL/target/trailing
   thresholds themselves are untouched. Given this touches the live
   position-management hot path, **I want your sign-off before
   implementing it** rather than pushing it through unilaterally like
   today's other fixes.
2. **Do not adjust `stoploss_pct`, `target_pct`, or `ema_rsi`'s
   thresholds based on today.** One trade, one session, and a mechanism
   that never got to run its exit logic is not evidence that any
   strategy parameter is wrong — changing them now would be fitting
   noise, not signal.
3. **Add a regression test** that opens a paper position and asserts the
   exit-check path actually evaluates on a subsequent tick, so this bug
   class can't silently return.
4. **Validation clock:** per the checklist's own rule ("any single
   failure resets the clock"), today does not count toward the
   10-session/30-trade window — not because of the entry bugs (fixed
   before the only real trade), but because the one trade that did
   happen was never risk-managed. Clock restart should be dated from

5. **Investigate the 16:34–20:20 IST log silence** and the 15:15–15:25
   candle anomaly before relying on this environment's after-hours

## 8. Exit-monitoring fix — validation results (21:09 IST restart)

**What was fixed:** `on_tick()`'s position-matching now includes option
positions (previously excluded by design), and fetches the option's own
live premium on demand for every exit-side decision (hard SL/TP
interceptor, `exit_engine.evaluate_exit` trailing-stop path, pyramiding
scale-in — same bug, same fix, found while making this change) instead
of comparing the underlying index price against option-premium
thresholds.

**Verified:**

- Full test suite: 95/95 passing, no regressions. (One test-hygiene
  incident during this: `test_order_rate_limit.py` wrote 2 fake trades
  directly into the live `state.db` — cleaned up immediately, see
  `anomaly_log.md`. This test file is not isolated from the real DB;
  avoid running the full suite against this environment until that's
  fixed.)
- Restarted the engine at 21:09 IST. It correctly loaded the stale
  position from disk, detected via `sync_broker_state`'s reconciliation
  path that the paper broker showed it flat, and closed it — logging the
  mismatch and its own estimate clearly rather than silently trusting a
  stale number. This is a genuine, working safety net (checklist §2.6
  territory) and closed out the dangling position from today, which was
  the right operational outcome regardless of the PnL-sign issue below.

**Not yet observed live:** the stale position was closed by the
*reconciliation* path (which runs once at startup/reconnect and is

`on_tick` fix directly. No new entry has fired since restart (real NSE

**EOD exit logic: does not exist.** Confirmed again on restart — there is

This was never part of what was fixed tonight (out of scope of the
approved change) and cannot be "validated as functioning" because

**New finding, not yet fixed:** the reconciliation event that closed
today's position logged it as a **+21.95 profit for a stop-loss hit** —
which is definitionally impossible (a stop-loss caps a loss, it cannot

correct for a genuine short position but wrong for a bought PUT (this
system only ever buys options — CE/PE already encodes the directional
bet, so `side` shouldn't flip the sign again). Full detail in
`anomaly_log.md`. **Not fixed** — distinct issue from tonight's approved
scope, flagged for sign-off.
