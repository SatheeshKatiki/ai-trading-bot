## 3. Root causes (condensed — see `anomaly_log.md` for full detail)

1. **No detection for a silent tick feed.** `on_tick()` — and everything
   inside it, including all exit management — only runs when a real tick
   arrives; nothing else on a timer. A position opened off one stale
   snapshot then went unmonitored for 7h49m with nothing reporting it.
   Fixed: `shared/risk/tick_staleness.py` (`find_stale_positions` for open
   positions, `seconds_since_any_tick` engine-wide), wired into a 30s
   watchdog task. Observability only — no auto-halt, no forced exit.
2. **No gate on entries outside real trading hours.** A real broker
   enforces this structurally; paper mode did not. Fixed:
   `shared/market_hours.py::is_market_open()`, mirroring the frontend's
   existing `isMarketOpenIST()` definition, gating new entries only.
3. **CPU livelock — pandas `Index.insert()` under incremental column
   assignment.** Three hot-path functions built their output DataFrame one
   `df["x"] = value` column at a time; under pandas 3.0.3 this was
   observed to become catastrophic in a long-running process. Fixed by
   assembling every output as a dict of Series and constructing the
   DataFrame exactly once. Verified against real data at multiple sizes
   up to the full ~22,800-row cache; both `supertrend` and
   `generate_signals` confirmed to still never mutate their caller's
   DataFrame. **Not proven under sustained load for longer than today's
   observation window** — see §7.

All four fixed, 313 tests total (49 new today across
`test_tick_staleness.py`, `test_market_hours.py`,
`test_incremental_column_insert_regression.py`, plus the earlier
SL/ATM-ITM/instrument-focus suites from the same session), 1 pre-existing
order-dependent flake in `test_panic_exit.py` unrelated to today's
changes (passes in isolation). Six commits, all local, none pushed.
